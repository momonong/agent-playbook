## 決策

- 原本新建任務的 GPT-6 Sol 更新為 GPT-6.1 Sol (`gpt-6.1-sol`)；Astra、Luna 及 High／Medium 分配保留。依據與限制見 [模型指南](../guides/model-selection.md#2026-10-02-模型更新)。不因新模型推出而全面升級到 Astra，也不另做未授權 benchmark。
- 保留足夠的全域核心說明：目標、三種角色、授權、資料保護、完成與回報、選型摘要和指南入口。完整細則按需讀取。
- 位置解析區分目前 repo、其他專案集合、Codex home；各 OS 使用原生主目錄與路徑 API。原先 Windows 僅沿用已確認目錄的規則擴充為：已指定／登錄目錄仍優先，環境變數其次；未設定時原生主目錄下的 projects 可作存在性核對的候選，不自動建立。
- 新增零第三方依賴的安裝程式：預覽、原檔 hash 核對、備份、固定 commit 快照、原子替換、冪等更新與衝突停止。不保存裝置專屬路徑到 repo。
- 原始 16 節歷史檔保持位元組不變；main／orchestrate 角色限制、精簡派工路徑、正式批准與現有工作保護維持。

- 唯一核心入口仍是 `instructions/codex.md`，移除兩個待替換佔位符與裝置路徑。README 將直接複製作為第一個使用方式；安裝程式改為可選。
- 核心固定釘選詳細指南 commit，按本機快照 → repo 指定版本 → GitHub 同一版本定位。遠端只讀所需文件，不自動 clone、安裝、切分支或採用最新草稿。無法取得時保留核心邊界並回報受影響工作。
- 本輪四份 guides 沒有改動，繼續使用已合併版本 `4b851a2bb8f4d3eec30535d678d003b001818b0f`；指南 commit 與核心來源 commit 分開保存，避免 Git commit 自我引用。

## 同日後續：減少跨對話重複批准

使用者指出常被要求複製批准文字到特定對話；在討論階段內溝通授權、可查證的原始授權與原 task 回報後，明確要求「好 那我們把這些都完成」。本輪完成上述政策修改，沿用此 repo 的驗證、版本合併、推送與本機指示更新授權，不重啟其他專案被拒的操作。

- 核心保留簡短的適用條件與邊界；[合作指南](../guides/collaboration.md#授權傳遞與決策)展開參與者 ID、溝通方向、用途、資料範圍及原始人類授權核對。授權限於使用者另行批准的具體階段與指定參與者，不擴成全帳號互傳或外部通訊授權。
- 派工時預先約定成果留在原 task，由協調者透過允許的事件／wait／read 取得；有新指令、澄清或相依阻礙才主動傳訊。回報責任仍在，減少重複傳送與人工搬運。
- 正式批准優先用客戶端實際提供的介面；若必須在執行 task 直接確認，說明工具要求、動作、資料範圍與最少步驟。代理不能代批准，不能用讀取、檔案或其他對話繞過拒絕，也不能藉此降低安全政策。
- 保留角色限制、既有模型與推理分配、Git／部署逐項授權、資料與服務保護、跨裝置定位。歷史原文與既有指南快照不變；核心改釘選本次合作指南版本。
- 依據：[Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)、[Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security)。指示詞可減少可避免的重問，不能保證所有工具都接受跨對話證據；未以真實專案傳送驗證自動審查結果，不宣稱已消除全部批准要求。
