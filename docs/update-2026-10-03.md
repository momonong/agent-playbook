# 2026-10-03 對話角色命名

## 決策與範圍

使用者確認 main → task 的精簡路徑可接受，問題是側邊欄名稱看不出角色，因此要求將命名方式加入完整指示詞，完成合併與推送，供直接複製使用。

- [核心指示](../instructions/codex.md)加入簡短命名規則；[合作指南](../guides/collaboration.md#對話命名)保存格式、範例、交接核對與工具失敗處理。
- 已確認角色的對話使用 `main：專案`、`orchestrate：專案／階段`、`task：專案／具體工作`；main 可依需要補主題，使用者明確指定的名稱優先。
- 建立、fork、交接或沿用相關對話時按已確認角色設定名稱；不批次修改無關對話，也不藉命名推定權限。一般問答與內部 subagents 不強制套用。
- 不加入狀態、模型或推理深度，避免反覆改名。工作範圍實質變更才更新描述；角色變更另須確認。
- 本輪只更新政策來源與 GitHub 交付，不改名 KaChing 或其他既有對話；不新增「新對話預設 main」規則，不改動分工、模型、操作授權或批准機制。

## 驗證

核對核心與指南語義一致、完整核心仍可跨裝置原樣複製、四份指南符合固定版本、文件連結與 diff 格式、歷史原文 hash。沿用現有安裝測試及三平台 CI；不以文件驗證宣稱所有既有對話已重新載入或改名。
