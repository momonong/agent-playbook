# 2026-10-09 專案學習主軸與 learn 對話

使用者確認每個個人專案各有學習對話，並澄清：每個專案應有自己的主軸，學習與它相關的概念及知識；開發成果提供案例，並非每次變更都要轉成教材。本輪授權更新本 repo 與說明核心指示更新方式。

## 需求映射

| 已確認需求 | 文件與行為 |
|---|---|
| 每個指定個人專案各有一個學習入口 | [核心](../instructions/codex.md)與[合作指南](../guides/collaboration.md)新增 learn，沿用或經建立授權後新增；不批次建立所有專案對話 |
| 以專案主軸學習概念與知識 | [學習指南](../guides/learning.md)由已確認主軸、目標與先備關係安排路線，允許回補基礎或深入，不按 commit 排課 |
| 開發持續且使用者可以晚間學習 | 已授權開發階段依原上限及停止條件推進；學習未完成不阻塞其他工作、不代表人工驗收，也不自動啟動新階段或排程 |
| 保留 main 的決策入口 | main 負責專案決策、交付與驗收；learn 負責教學與已授權學習筆記，不派工或修改工程實作、需求、驗收 |
| 使用者不用搬運成果 | main／learn 事先約定 ID、讀取／傳訊方向、用途及資料範圍，依工具與人類授權取得來源，不把教學角色當作全帳號存取權 |
| 知識能跨對話及裝置接續 | 共通方法放 playbook；主軸、路線、來源版本、學習進度沿用各專案文件，不複製聊天或另建平台 |

學習進度需有依據，區分已討論與已展現理解；不因代理完成工作就推定使用者已掌握。模型、effort 與速度政策未變，本輪不設定 learn 專屬模型。

## 核心更新與交付

- 完整核心來源仍為 [instructions/codex.md](../instructions/codex.md)。更新包含 learn 角色／命名、開發與學習的交接、學習指南觸發入口及新版 guides-commit。
- 新增第五份指南後，現行維護與安裝說明改為核對「核心引用的所有指南」。歷史遷移文件中當時的四份指南描述保留。安裝程式原本就保存指定 commit 的全部 Markdown，沿用該行為；既有測試增加學習指南版本與快照內容核對。
- 固定指南需先建立本機指南 commit，再更新核心 pin。尚未推送時，這個版本只在本機可取得，不能宣稱其他裝置可從 GitHub 讀取；GitHub main 仍是上一個正式版本。
- GitHub 交付完成後，整份複製核心替換 Codex 個人指示即可；不要只附加 learn 段落而漏掉新版指南 pin。詳細指南不必另貼，既有批准 Custom rules 不需因此修改。
- 本輪未授權合併／推送、安裝全域指示、建立各專案對話或排程；這些狀態須分開回報，不因文件更新宣稱已生效。

驗證涵蓋文件連結、UTF-8、歷史原文 hash、核心可攜性與大小、所有指南的固定版本、角色／授權一致性，以及既有安裝測試中的學習指南快照。未執行的跨平台 CI 與跨對話教學流程不列為已通過。
