# 2026-10-16：一個對話承接一個目標

## 使用者決策與授權

同一對話先討論，授權後直接實作；目標明確且已授權時可直接開始。使用者確認：「好 那就改成這個方式 幫我更新 repo 裡的文件和這台電腦的 codex instructions 然後合併推送 舊對話先保留不要刪掉」。

本次涵蓋文件、Git 交付與本機指示安裝；不涵蓋刪除／封存／批次改名舊對話、切換既有模型、啟動或移交其他專案工作。記錄決策摘要，不保存完整私人聊天。

## 需求映射與取代範圍

| 決策 | 主要落點 |
|---|---|
| 同一目標從討論到實作、驗證、回報；主對話可以實作 | 核心、合作指南「一個對話承接一個目標」、工程指南 |
| 先討論不等於執行授權；已授權不反覆確認 | 核心、合作指南 |
| 同一問題留在原對話；獨立目標才考慮新對話 | 合作指南「對話命名與既有工作」 |
| 不再強制 main／orchestrate／task 分層與集中 main 回報 | 合作指南、README、外部執行／服務／學習指南 |
| 有收益才委派 subagents，原對話核對並直接交付 | 合作指南「Subagents 與外部執行者」 |
| 模型按工作性質選型，不強制 Astra → Sol；不改現有配置 | 模型指南；Astra Medium、Sol 6.1 High 等維持既有起點，不新增全域預設 |
| 保留舊對話與 learn／專利用途，政策不自動恢復或接管工作 | 核心、合作與學習指南 |
| 保留授權、正式批准、資料／服務保護與實際驗證 | 核心及各主要指南 |

取代早期歷史更新中的強制角色命名、main／orchestrate 禁止實作、固定派工路徑、角色模型綁定與強制回 main。2026-10-16 較早的回報修正中，「最新目標、證據、實際交接、不能拿舊 PR 代答」仍保留；強制逐層回 main 已由本決策取代。歷史文件保留追溯，不當現行指令。

必要且已授權的跨對話合作仍可使用，但不是每個目標的預設流程。正在執行的舊工作需在接續時核對承接者，不批次傳訊或重跑。
