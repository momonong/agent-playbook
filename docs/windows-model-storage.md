# 這台筆電的 Windows 模型權重存放

本規則專供**使用者指定的這台筆電之原生 Windows 開發環境**使用。該環境內各專案共用的模型權重根目錄為 `D:\hf_models`；這不是所有 Windows 電腦的預設。WSL、Linux、macOS、SSH、容器及其他機器不得直接套用，須另確認實際位置與掛載。

適用於 Hugging Face／HF、Transformers、SentenceTransformers、GGUF 等本機模型權重的下載、載入與存放；純遠端 API、沒有本機權重的任務不適用。

使用者於 2026-10-30 明確要求將這項非秘密存放規則寫入文件並合併推送，因此本文保留上述指定路徑。這是[裝置同步契約](device-sync.md)「本機路徑留本機」的單一窄例外，不擴張為私人裝置設定登錄表，不記錄使用者名稱、完整 config 或模型清單，也不將路徑寫入跨裝置核心。

## 下載與載入原則

- [全域核心的下載前規則](../instructions/codex.md#授權與保護)要求每個專案在下載前先讀適用的裝置規則與模型／快取設定，不只等待技能被自動選用。適用環境依實際執行下載命令的主機／OS 判定，不能用聊天視窗所在電腦代替。
- 只有下載在這台筆電的原生 Windows 本機執行時，才使用下列 `D:\hf_models` 規則。從 Windows 發出 SSH 命令到 Ubuntu，仍依 Ubuntu 的裝置規則、專案與已確認快取設定處理；不得把 Windows 路徑傳給遠端程式或在 Linux 工作目錄建立名為 `D:` 的目錄。
- WSL／容器須另核對該環境的目錄與實際掛載，不自行把 Windows 路徑轉成 `/mnt/d/...`。其他 Windows 裝置也須先確認自己的共用權重目錄；位置尚未確認時先核對，不假定同樣有 D 槽。
- 下載前同時查 `D:\hf_models`、`D:\hf_models\hub` 及根目錄下的一般模型資料夾；現有內容混合自訂模型與兩處 Hub cache，不假定只有單一 layout。
- 核對 model id、revision、格式／量化與所需檔案完整性。相容時直接使用本機模型路徑，或將實際命中的 Hub cache 根傳入 `cache_dir`；不為每個 repo、venv 或 worktree 再下載、複製一份，也不為統一路徑新增重複 cache。
- 缺少時，僅在當次已授權下載任務內，把缺少的版本／檔案補到共用根目錄下的合適位置。這項規則本身不授權下載或外部操作；沒有下載授權就回報缺件。
- `HF_HOME` 與 `HF_HUB_CACHE` 意義不同，前者還涉及 token 位置；不能把它們一律設成共用權重根。先定位實際 Hub cache，再優先使用明確 `cache_dir` 或僅限當次程序的設定，不自行改永久環境變數、config 或認證位置。
- 根目錄不存在、不可用或容量不足時，停止相依下載並回報，不默默回退 C 槽、專案內或其他預設位置。不因本規則搬移、刪除、清理既有權重或覆寫共用 snapshot。
- 微調／訓練 checkpoint 另依專案輸出約定保存，不混入共用預訓練權重。交付時回報實際復用／新下載位置、model id／版本與未確認項目；沒有量測就不宣稱節省量。

## 技能入口與驗證界線

`local-model-storage` 維持這台筆電的本機個人技能，供全域核心的下載前檢查及相關任務讀取；未加入[七包共用 manifest](../skills/manifest.json)。clone／pull 本 repo 或執行 `scripts/install.py` 都不會安裝這個技能，也不會設定 HF 環境變數。其他裝置不因取得本文就完成安裝或取得相同路徑。

2026-10-30 的狀態分開記錄如下：

- **檔案安裝**：本機技能已安裝；本次 repo 修改只補文件與入口，不改技能、模型權重或設定。
- **客戶端發現**：當輪 Codex 提供的技能清單已列出 `local-model-storage`。
- **功能與接受**：未執行實際模型下載／載入測試，未量測節省容量，也不保證完全沒有重複檔案；自動選用行為及使用者接受不能由檔案存在或技能清單推定。

上述界線不改變既有下載、私人資料、外部資源或 Git 操作的授權要求。

2026-11-02 補強全域核心的下載前必讀入口與上述執行端分流；跨裝置核心仍不含筆電的絕對路徑。這是 Codex 行動前的工作規則，不是攔截所有軟體下載的系統 hook。已開啟對話是否重新載入全域指示須另行核對，不能只由磁碟安裝成功推定。
