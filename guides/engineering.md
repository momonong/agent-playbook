# 工程、環境與交付

適用於專案修改、工作目錄、Git、Python、驗證、整合與清理。專案明確規範優先於本指南的一般工程預設；不得以此擴張使用者授權或略過資料保護。角色與派工見 [合作指南](collaboration.md)。

## 實作與除錯

- 進入專案先核對適用 AGENTS.md、目標／規格、當次相關程式碼、Git 及環境。利用可信摘要再驗證相關內容，不反覆全面調查。
- 在正確、可維護的前提下選最簡單且足夠方案；以理解、修改、驗證成本衡量簡潔。沿用架構、命名、工具與成熟元件，新增抽象、依賴或服務須解決當前問題。
- task 自主決定範圍內的私有函式、命名、測試與局部重構；跨 task 內部介面由 orchestrate 協調；外部契約或資源使用先核對當次授權。
- 先建立可核對現象、根因假設與驗證方式，再作有證據的修正。避免連續盲改、同時更動無法區分效果的因素、層層特例、吞錯誤或靜默 fallback。
- 保持清楚模組責任、介面及資料契約，提供必要驗證、錯誤處理與診斷，不為形式增層。效能先量測，不憑猜測廣泛重寫，不以犧牲正確性或驗收換速度。
- 緊密相關的分析、實作、測試、文件與修正留在同一 task。優先解決阻擋相依；共同介面清楚且可獨立推進才平行。
- 測試聚焦使用者可觀察行為、重要邊界與回歸，遵循格式、型別、靜態檢查及 CI。達成條件後收尾，不順便新增無關重構、文件或工具。
- 持續變慢或反覆出錯時，先區分模型判斷、需求、資訊、工具等待、環境、相依與協調成本，再對症處理；提升模型不能取代規格、資料及驗證。
- 專案目標／規格與決策保存依 [合作指南](collaboration.md)；AGENTS.md 只在共同工作規則改變時更新，架構與使用方式更新對應文件。

## 路徑與執行環境

- 共用指示使用專案相對路徑；工具需要時再解析絕對路徑，不寫死使用者名稱或磁碟代號。
- 當前專案優先沿用已指定目錄、登錄位置或實際 Git root；不因 OS 不同而搬移、複製或重建。
- 三種位置分別解析：當前 repo 用已指定／登錄位置或實際 Git root；其他專案的集合目錄用已確認位置，其次為既有 `PROJECTS_ROOT`；Codex 設定目錄用已確認的客戶端設定或該執行環境的 `CODEX_HOME`，未設定才用原生使用者主目錄下的 `.codex`。不以 repo 位址推導 Codex 設定位置。
- `PROJECTS_ROOT` 未設定時，各平台都可將原生主目錄下的 `projects` 當候選，只有存在且內容符合才採用。Windows 不預設 C 槽、OneDrive 或 Documents；macOS／Linux 也不寫死 `/Users` 或 `/home`。明確設定的位置無效時回報，不默默退回另一份 repo。
- 上述變數只是可選約定，不代表已存在，也不授權修改系統或 shell 設定。GUI App 與終端可能繼承不同環境；用實際執行端核對，終端設定不代表 App 已取得。
- 程式使用原生主目錄／路徑 API；文件中的 `~` 代表主目錄，不假設每個工具會展開。參數路徑加引號；設定變數建議用完整原生絕對路徑，不將 `%USERPROFILE%`、`$HOME` 等未展開字串交給另一種 shell。相對路徑須先說明解析基準；無基準時不猜。
- Windows 的磁碟路徑、UNC、Linux/macOS 路徑分別在原生環境解析。WSL／SSH／容器視為不同環境，不自動把 Windows 路徑轉成 `/mnt/...`，或把本機路徑傳給遠端。使用者指定且可存取的網路路徑可沿用；涉及寫入時仍核對權限與檔案系統能力。
- 文件中的 `<projects-root>` 是解析後的位置，不是字面路徑。找不到時先查已知設定與位置，仍缺必要資訊才詢問；不盲目掃全磁碟或建立目錄。
- 執行前確認 OS、shell、工具與主機；使用正確引號、變數語法及路徑 API。注意大小寫、空白與執行權限；不假設有 Bash、PowerShell 或相同工具。
- 共用腳本沿用既有跨平台方式；必要平台限定功能明確標示，不順便改無關程式。SSH 主機、WSL、容器與 VM 分別解析路徑與 localhost，主機路徑不直接套用。

## 工作目錄與隔離

- 同一專案預設主要目錄；已有指定目錄／worktree 就沿用。單一 task、循序修改、例行驗收與合併不預設新增 worktree，也不因另開對話或模型分工複製 repo。
- 確有多個 task 同時修改同一 repo，或不能干擾的未完成工作妨礙操作時才隔離；使用者明確要求時依要求。建立前查 worktree、分支與使用情況，說明起始版本、用途和具體原因。
- 乾淨目錄不代表無 task／程序使用；切換分支或整合前核對已知使用者與程序。無法確認且有干擾風險時先協調或必要隔離。
- 修改前確認目錄、分支／HEAD、起始 commit 與未提交變更。保留使用者及其他任務工作，不覆寫、不回復、不提交無關內容。
- 平行修改使用各自 worktree 與工作分支，記錄相依及起點；不同 branch 名稱不等於不同目錄，subagents 不自帶隔離。
- Worktree 不隔離資料庫、Docker、port、GPU 或外部資源；先核對共用影響。依專案準備新 worktree 的依賴、設定與資料，不假設環境相同。
- 臨時驗證固定 commit 且確需額外目錄時，優先 detached HEAD。分支已被占用先查用途，不繞過 Git 保護或直接刪目錄；可從該 ref 建新分支，不必先 checkout 它。

## Git 分支與提交

- 遵循專案規範；未定義時用聚焦可驗收問題的短期工作分支，不混無關修改、不增加不必要的 develop／release 長期分支。
- 功能、修正與衝突解決在工作分支進行，避免直接於 main 開發；已有符合範圍的分支優先沿用。
- 預設 `<type>/<short-description>`，type 為 feat、fix、refactor、perf、docs、test、build、ci、chore、revert、integrate；簡短具體英文小寫與連字號，避免 temp／misc／final、姓名、空白及底線。
- 有既有 issue 可加編號，不虛構。功能的測試與文件留在同分支，不按檔案種類拆分。
- 建分支前確認目錄、狀態、起點與合併目標；需對齊遠端先 fetch，不盲目 pull。名稱存在時查用途及 worktree，不強制重設、覆寫或直接沿用。
- 相依工作可從指定前置 ref 建立，記錄相依和合併順序，避免夾帶無關提交。
- 未有專案規範時，共用或被依賴分支優先 merge；rebase 僅用於確認未共用、未被依賴的私人分支。改寫已推送歷史與 force push 需明確授權；必要且已授權時核對遠端後用 --force-with-lease。
- 提交只 stage 本次明確檔案，檢查 staged diff、敏感資訊與產物。合併、推送及清理按當次授權；分支完成不自動擴張交付範圍。

## Python

- 新 Python 專案或獨立工具預設 uv；以 pyproject.toml 宣告依賴、uv.lock 固定解析，一般納入 Git，.venv 不納入。
- uv sync 建／同步環境、uv run 執行、uv add／uv remove 管依賴。重現驗證優先 uv sync --locked 與 uv run --locked，遵循專案規範。
- 避免在共用文件／腳本寫死 .venv 內平台限定執行檔或啟用命令。不要改全域 Python，或混用 pip／Poetry／Conda 修改同一環境；特殊安裝核對規範及相容性。
- 既有專案沿用原工具，未獲同意不遷移 uv。不順便升級依賴；檢查 pyproject.toml／uv.lock diff 並驗證。
- 各 worktree 自行依規範建環境，不共用其他 worktree 的 .venv、不跨 OS／電腦複製 .venv。Python、套件來源、CUDA／PyTorch 依相容性要求，不換成假定最新。
- OS／硬體限定依賴清楚區分；一個平台通過不代表其他平台通過。

## 驗證與整合

- 驗證與風險、修改範圍相稱。task 驗實作；orchestrate 核對是否支持階段驗收，不為角色分工重跑充分檢查。
- 同版本、環境、適用範圍的證據可重用；新變更、失敗、環境／版本差異、未驗證組合或疑慮才補受影響檢查。
- 標明 OS、環境與版本，以及未驗證平台。不能將編譯、局部測試、服務啟動或更強模型當整體品質／人工接受證據。
- 整合前核對來源 branch／commit、目標版本與交接狀態。單一驗證成果的循序合併，優先由 task 在可用且乾淨的主要目錄完成。
- 多成果整合、衝突解決或組合驗證使用整合分支；不必另建 worktree，除非主要目錄被占用或有不可干擾的工作。
- 理解並保留各需求，不任意選單邊衝突內容。即使 Git 無衝突，也核對介面、資料、設定及整體行為相容。
- 未決取捨由 orchestrate 核對授權，超出交 main；適用精簡路徑則直接交 main。最終目標內容不同於已驗證版時補驗受影響範圍。
- task 更新受影響文件及證據，orchestrate 核對階段條件；使用者需要人工驗收時，標示待驗收。

## 交付與清理

- 合併、推送、發布、部署、刪分支與移 worktree 依明確授權；已授權者檢查後直接執行。orchestrate 協調範圍，task 執行並回報。
- 收尾盤點本次臨時目錄、分支與執行資源；保留時說明用途、原因及影響。不停止其他服務、不刪共用資料。
- 釋放分支／清理前確認無使用中的 task／程序、未保存變更及相依，成果已整合或另有保存。不讓無用途的臨時 worktree 默默占 main。
- 已授權移除 worktree 時用 git worktree 管理，不直接刪目錄或強制忽略變更；未授權列出保留項目及建議。
- 已授權合併收尾且主要目錄可用時留在 main 或指定分支；無法恢復時說明原因及分支位置。
- 本機 commit、遠端 push、PR／merge、發布與部署分別報實際狀態；未驗證、未完成與已變更需求清楚列出。
