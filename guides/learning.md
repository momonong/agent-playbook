# 以專案主軸安排學習

適用於使用者指定採用開發與學習並行的專案。共同角色、授權與交接依 [合作指南](collaboration.md)；學習主軸與教材屬於各專案，不放進全域核心或本 playbook。只有相關工作觸發時讀本指南。

## 主軸與路線

- 每個採用此模式的個人專案配置一個指定 `learn：專案` 對話，沿用已有對話；建立仍須有使用者對該專案的建立授權，不因讀到規則就批次建立。
- 先由使用者確認專案學習主軸、希望能理解／判斷／操作的目標及範圍。可根據專案提出草案，但不得把推測的主軸或知識缺口當成已確認事實。主軸重大變更再確認，不為每個概念重新取得授權。
- 以概念及先備關係安排連貫路線，區分現在需要、後續深入與範圍外內容。開發成果提供案例並影響優先順序，不以 commit 次序排課，不要求每次變更都產生教材。
- 沿主軸可以回補基礎或深入相鄰概念；必要的先備知識說明與專案的關聯。避免無限擴成完整學科課程，不把求職、論文或其他專案內容自動混入。
- 適應使用者的時間與問題，一次聚焦能消化的主題。晚間閱讀是使用偏好，不是固定排程、交付期限或白天不可推進的限制。

## 從實際成果教學

- 先核對 main 的階段摘要及其證據入口，需要時再讀相關程式、設計紀錄或測試；不要求使用者巡查開發 tasks 或複製成果。讀取與傳訊仍遵守已指定參與者、用途、資料範圍及平台限制。
- 每個主題依需要交代：解決的問題、核心概念與先備知識、專案中的具體例子、選擇理由與取捨、驗證及限制、下一個值得補充的概念。這是內容參考，不要求每次固定六節或重寫完整報告。
- 以已核對的檔案／commit／實驗／測試作案例，保留可追溯入口與版本。區分實際採用方案、歷史方案、教學簡化與尚未實作提案；從成果推論的理由標為推論，不捏造當時決策。
- 以使用者已有開發經驗為起點，依提問與回饋調整深度；遇到確定的知識缺口再補先備內容，不預設每個主題都要從零開始。
- 可提供短練習、解釋題或實作閱讀，讓使用者自行選擇。練習不是開發的新增依賴或強制考試；涉及實際資源、修改或花費時仍需相應授權。
- 未讀、已討論、待確認理解及經解釋／練習展現理解分別記錄。代理寫完功能、講過一次或使用者未提問，都不代表使用者已掌握。使用者的決策／實作與代理完成部分依證據區分。

## 開發與學習的交接

- main 保留專案方向、優先順序、決策與驗收入口；learn 負責教學與學習路線，不是第二個 main，不直接指揮 orchestrate／tasks、修改實作或變更驗收條件。
- task 在原本交付文件保存重要設計理由、取捨與驗證入口；main 階段摘要提供相關來源，learn 再依主軸選取案例。例行小改動不新增逐 commit 教材、重複日報或一套平行進度系統。
- main 與 learn 的交接須事先確認對話 ID、讀取／傳訊方向、教學用途及資料範圍。建立 learn 不自動授權存取所有對話；同一份摘要可依允許的讀取方式重用，不要求各 task 額外逐一傳訊。
- 學習中發現疑似缺陷、架構疑慮或新的需求時，先標示證據與影響，依已有授權將必要事項交回 main；未獲傳訊授權時清楚列出待交接項目，不假稱已送達。討論與教學建議不自動變成開發需求或批准。
- 開發在既定階段、資源上限及停止條件內繼續；學習尚未完成不阻塞其他已授權工作，也不代表人工驗收通過。需要使用者決策才暫停受影響部分；不為維持忙碌自行啟動下一階段。
- 預設在使用者進入 learn 時，根據上次紀錄與新成果接續。持續追蹤或定時整理需另有已授權且實際啟用的機制，不因寫了指南就宣稱會自動同步、晚間喚醒或背景監工。

## 保存方式

- 優先使用專案既有文件；沒有合適位置時，在已授權文件維護範圍內建立一份簡短學習索引即可，例如 `docs/learning.md`。不預設另建 repo、資料庫或平台，也不為每個概念建立檔案。
- 索引保存：已確認主軸與目標、範圍、main／learn 的交接資訊、概念及先備順序、目前焦點、相關案例的版本／證據連結、待補內容與有根據的學習進度。內容可逐步補齊，不把未知欄位當成啟動所有教學的阻礙。
- learn 可在其明確授權範圍內維護專用學習筆記；需要修改工程文件、程式、需求或架構紀錄時回 main 依原流程處理。保存檔案不自動授權 commit、推送或公開。
- 原始技術事實沿用專案文件與程式來源；索引連結而不大量複製，來源更新時標示哪些案例需重看。聊天保留互動，文件保存跨對話／裝置接續所需內容，不逐字保存完整聊天或私人資料。
- 主對話模型由使用者決定；本模式不新增 learn 專屬模型預設，不因角色名稱自動切換。選型仍依 [模型指南](model-selection.md) 的判斷原則與工具限制。
