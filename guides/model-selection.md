# 模型與推理深度

這是使用者對**由 Codex 執行的已授權新任務與 subagents**的配置政策，不是模型能力保證、官方最佳設定或切換既有對話的授權。主對話模型與 effort 由使用者決定。

## Astra 討論、Sol 6.1 實作

使用者於 2026-10-18 確認：Astra Ultra 負責討論、決策、推進與最後核對；Sol 6.1 Ultra 只承接已確認且已授權的實作。Astra 持續作為原目標對話的使用者入口，不強制 main／dev 前綴，不恢復 main／orchestrate／task 分層，也不按模型另建聊天。

- Astra 釐清需求、目標、研究假設與重要取捨，在既定授權內決定開發方案（dev plan）；可直接讀檔、查證與做探索性小測試。方案確認後，實作、除錯、執行驗證與必要文件預設交 Sol 6.1 Ultra subagent；使用者另行明確指定時才採其他承接方式，不預設將使用者主對話切成 Sol。
- Sol 可自主思考並處理範圍內的局部實作細節、方法與落地步驟；不能變更目標、範圍、研究假設、重大架構或驗收條件。遇到上述變更先交回 Astra，需使用者決策時由 Astra 提問；不得把實作便利當成需求變更授權。
- Astra 跟進助手進度、要求必要修正，查證並整合結果後直接交付使用者，不停在「已派工」或助手 final。同版本、環境與範圍的充分證據可重用；等待與停止條件依[合作指南](collaboration.md#持續工作停止與暫停)，沒有跨回合喚醒機制就不承諾自動監工。
- 不把所有可逆工具操作都當成開發實作：Astra 可直接做查證／核對所需測試、微小機械操作，以及已授權的 Git 交付與本機安裝，不為這些步驟強制派工。
- 這是後續工作安排的使用者偏好，不是批次切換既有對話或設定的授權。既有對話、learn／專利用途、模型／深度與暫停狀態保留；接續前核對實際設定，需調整時依當次授權與平台規則辦理。

## 模型與深度預設

| 工作性質（需要選型時） | 模型 ID | Effort 預設 |
|---|---|---|
| 討論、決策、開發方案、推進與最後核對 | `gpt-6-astra` | `ultra` |
| 已確認且已授權的實作、除錯、執行驗證與必要文件 | `gpt-6.1-sol` | `ultra` |
| 機械轉換、資料抽取與結構化整理 | `gpt-6-luna` | `high`；簡單且可可靠驗證時 `medium` |

- Astra／Sol 的 Ultra 是使用者目前偏好，不是能力限制或已證實最佳組合；不因文字政策宣稱工具已切換模型。Luna 維持上表設定，外部工具依下節另行核對。
- 主對話模型由使用者決定；工具若要求未指定模型時沿用使用者配置，依工具規則辦理。只有選型與建立均已授權時才提供明確參數，不以表格自行建立對話。
- 依不確定性、錯誤代價、可驗證性及總交付成本選擇。可用既有工具處理的機械步驟，不為模型分流增加 task；不同模型同名 effort 不代表能力或費用等價。
- 既有對話恢復前核對實際設定，差異僅說明；取得切換授權後才調整。不以設定訊息偷偷喚醒暫停工作。

## 外部 task 的設定

- 外部 CLI task 的執行與驗收依 [外部執行指南](external-execution.md)。本指南 Codex 的模型、effort 與速度政策不自動套用 agy 或其他工具；保留既有 Codex 任務配置，不因增加執行者切換模型。
- 使用該工具實際支援且已確認的模型／effort；任務或階段交接記錄工具版本、供應商、模型、effort 及其回傳核對結果。未指定時先提出合適配置並確認必要選型，不把工具預設或 latest 當成已確認值。
- 不因不同工具都稱 High 就視為能力或費用等價，也不照搬 Codex model ID。較深設定或更新模型不代表更有效率，不自動啟用額外付費、升級訂閱或全面提高深度。
- 規格清楚、容易驗證的簡單 task 可以外派；交接成本大於收益時沿用既有執行者。評估總用量、返工及完成時間，不以形式分工為由多開一層 Codex task。

## 深度、速度與變更

- Astra／Sol 預設 `ultra`；後續改深度需使用者決策，不自行修改全域模型 config、既有聊天 effort、訂閱或額外付費。不因額度剩餘自動提高其他模型，也不因單次消耗高就立即降低深度。
- 先核對需求、資料、工具、環境與相依，再處理反覆漏約束、根因判斷不足與無效修正。工具故障、批准阻礙、缺資料與純等待，不能靠升級模型解決。
- Effort 與速度分開。新任務工具可指定速度且無另行要求時使用 Standard；Ultra 不代表 Fast。工具沒有速度欄位時不宣稱已設定或驗證 Standard。
- 更深推理不保證更快、更正確，仍須完成與風險相稱的驗證。追求總交付效率、減少返工與人工介入，不追求最低單次 token 或用完額度。

## 實際設定與權限

- 只有任務建立已獲授權才使用上述預設；本指南不授權新建任務、改設定檔或切換現有模型。延續既有 task 時保留既有設定，除非使用者另有授權。
- 工具支援時在參數明確傳入 model／effort，不只在 prompt 中描述。以工具回傳或可查詢設定核對；僅知道送出參數時應說「已請求」，不可說已驗證實際執行設定。
- 指定模型不可用時不擅自替代；說明工具限制與已知狀態，繼續不依賴該選型的工作。不為更換模型另開重複 task。
- Subagents 依上述分工與當次授權選型；若無法指定或只能繼承，回報實際限制，不把繼承模型當成已指定 Sol 6.1，也不默默改用其他模型完成受指定模型限制的工作。提供足夠背景與範圍，結果仍由原目標對話核對；不依賴該選型的工作可繼續。

## 評估與版本

- 優先利用數個代表性完整任務的完成時間、人工介入、返工、驗收及用量判斷，不看單次回答長短。
- 不自行建立額外 benchmark、重跑完整工作或新增監控；額外實驗需先確認範圍。外部評測只提供起點，不能取代本專案證據。
- 模型更名、可用性或政策更新時，保留此版本的已確認 ID，經使用者決策後更新；不把查到的新模型自動替換進配置。

## 歷史決策與證據邊界

2026-10-18 的[Astra Ultra 目標責任決策](../docs/update-2026-10-18-astra-ultra-ownership.md)取代[同日上一版](../docs/update-2026-10-18-model-and-branch-policy.md)的 Medium／High 起點、Ultra 非日常預設及原對話切 Sol 的並列承接方式，改為上述 Ultra 預設與 Sol subagent 路徑。前版取代 2026-10-16「多數目標由一模型到底」的安排仍有效；[單一目標對話決策](../docs/update-2026-10-16-goal-conversations.md)中不按模型另建聊天、不恢復固定角色流程及原對話直接交付仍保留。歷史模型變更見 [2026-10-02](../docs/update-2026-10-02.md)、[2026-10-12](../docs/update-2026-10-12-lean.md)及[2026-10-13](../docs/update-2026-10-13.md)，不將歷史角色預設重新套用。

本政策不宣稱官方認證或已在使用者專案勝出。更新指示不會切換既有模型、全域模型設定或訂閱權限；實際可用 ID 與 effort 依執行端核對，API 與 Codex 工具選項不互相推定。
