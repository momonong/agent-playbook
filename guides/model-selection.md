# 模型與推理深度

這是已授權工作中的模型選擇政策，不是自動建立任務、切換既有聊天或使用外部供應商的授權。2026-11-02 使用者確認按目標調配，取消固定 Astra／Sol 分工與 Ultra 日常預設；原目標對話持續承接、核對並交付。

## 先看目標，再選配置

- 在目標開始或難度／風險有實質變化時，先確認交付物、驗收方式、主要不確定性、錯誤代價及可用資源，再選足以完成工作的模型與深度。同一階段沿用已確認配置，不為每個小步驟重新選型。
- 衡量完整交付成本：推理、上下文、工具、等待、派工、交接及返工都算。最低單次用量、最高深度或用完額度都不是目標；不為省額度降低驗收。
- 規格清楚且結果容易核對時採較精簡配置；高風險、跨模組或難驗證的工作直接採足夠配置，不為形式先用低配試錯。已有證據足夠時收尾，不再加一輪代理或重跑驗證。

## 工作起點與調配

下表是選型起點，須依實際目標判斷；不是每項工作都從 Medium 逐級試起，也不是自動調整正在執行的模型。

| 工作與判斷條件 | 建議模型／深度 |
|---|---|
| 搜尋、檔案比對、格式轉換、已知命令等確定性操作 | 優先既有工具／腳本，不另派模型；確需語意處理且易驗證時可用現有 Sol 6.1 Low，或已可用的 Luna Medium |
| 目標清楚的一般實作、文件、查核、教學與日常研究整理 | `gpt-6.1-sol`／`medium`，由原對話完整承接 |
| 複雜除錯、多模組整合、較難驗證的實作或明確高風險變更 | `gpt-6.1-sol`／`high`；先說清要解的風險及驗證方式 |
| 高不確定研究、重大架構取捨、跨領域推理，或有證據顯示需要不同模型能力 | `gpt-6-astra`／`high`；不因任務名為「討論／審查」就固定選 Astra |
| 上述配置仍不足，且額外推理有具體預期收益的困難問題 | 在工具實際支援的 `xhigh`／`max`／`ultra` 中選擇；說明要解的盲點、工作範圍、驗證及停止條件，完成後回到後續階段所需配置 |

- 本機新工作階段的一般起點與未明示配置之 subagent 保底值採 `gpt-6.1-sol`／`medium`。任務本身的選型仍以上述判斷為準；不把保底值當成所有工作的強制上限或下限。
- 不再要求 Astra 決策、Sol 實作，或把完整工作強制交給另一模型。原目標對話對決策、實作整合、驗證及交付負責；使用哪個模型不改變責任。
- 模型 ID、effort 與速度須依當台工具支援核對。不同產品的深度名稱、API 價格與 Codex 訂閱額度不直接換算，不宣稱固定節省比例；不因清單出現新模型就自動改預設。

## 升降與停止

- 普通工作不預設 Ultra。升級須有具體原因，如規格衝突、重要風險、推理盲點或現有配置無法達成驗收；不以「更保險」作為所有階段高配的通用理由。
- 先排除資訊不足、環境、權限、工具、相依及無效重試，再判斷模型能力。相同失敗原因不藉升深度、換模型或增加代理重做一遍。
- 困難決策已收斂、後續只是明確實作或整理時，改採該階段所需配置；避免把一次高配沿用到整個目標結束。平台不能在原對話切換時，不另建聊天來做模型轉傳；提供所需調整或在已有授權的分工中選型。
- 只以可用額度與已確認資源安排工作，不預支未取得的 reset 或額外付費。看到剩餘額度不自動升級，用量緊縮也不靜默降低驗收；不足時縮小已確認的執行範圍或回報停止點。

## Subagents 與上下文成本

- 已授權工作預設先由原對話完成。只有子工作可獨立推進且預期收益大於背景傳遞、協調與整合成本，才依[合作指南](collaboration.md#subagents-與外部執行者)委派；不因固定角色或每個階段都配審查者而派工。
- 交接只給目標、範圍、必要檔案／契約、驗收與既有證據。預設精簡上下文，不複製整串歷史、長日誌或全部工具說明；確有相依才補相關部分。
- 在可指定的工具參數中明示 model 與 effort，避免意外繼承主對話的高配。新 subagent 的一般起點是 Sol 6.1 Medium；需要不同配置時仍按目標選擇，不為機械小操作另派 Luna。
- 同版已讀文件、充分驗證與工具結果依既有規則重用；重跑須由新變更、失敗或未解風險支持。代理完成仍由原對話核對整合，不要求使用者搬運結果。

## 設定、權限與外部執行者

- 政策及裝置預設依當次授權更新；既有聊天的模型／深度、暫停狀態、插件、其他設定及其他裝置保留。修改全域檔案須備份必要欄位、核對 CAS 與結果，不宣稱文字規則已切換正在執行的模型。
- 任務建立、跨對話、新外部供應商、登入、服務、Git 與額外付費仍各依當次授權及平台工具規則。模型路由不授權建立新聊天或恢復工作；主對話模型的實際切換仍由使用者決定。
- 延續既有聊天時核對其實際配置；若明顯不合目標，一次說明必要調整，不反覆確認同範圍的例行步驟。工具無法指定時回報限制，不把推送參數當作已驗證的實際配置。
- 使用者明確指定的模型不可用時先回報，不悄悄替代；沒有指定時才依目標及可用能力選型。政策調整不授權自行使用 reset 或購買額度。
- 外部 CLI 的選型與執行依[外部執行指南](external-execution.md)，確認其模型、effort、資料與資源授權；不照搬 Codex 的 ID 或深度名稱，不自動開付費 fallback。
- Effort 與速度分開。可指定速度且未另行要求時用 Standard；工具未提供速度欄位就不宣稱已設定。不得因較低深度而切 Fast 或增加付費。

## 評估與追溯

以代表性目標的驗收品質、完整時間、人工介入、返工及實際用量調整配置；沿用已有工作證據，不為本政策額外建立 benchmark、監控或重跑研究。OpenAI 的[推理深度說明](https://developers.openai.com/api/docs/guides/reasoning#reasoning-effort)可作一般選型參考；實際可用組合仍以本機平台為準。
