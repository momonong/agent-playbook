# 模型與推理深度

這是使用者對**由 Codex 執行的已授權新任務與 subagents**的配置政策，不是模型能力保證、官方最佳設定或切換既有對話的授權。主對話模型與 effort 由使用者決定。

## 預設配置

| 工作 | 模型 ID | Effort |
|---|---|---|
| 新 main：目標、研究、重要取捨與使用者驗收 | `gpt-6-astra` | `medium` |
| 新 orchestrate：工程拆解、安排與整合驗證 | `gpt-6.1-sol` | `high` |
| 新 task：具體問題的分析、實作與交付 | `gpt-6.1-sol` | `high` |
| Sol 無法解決且確需更深判斷的有界支援 | `gpt-6-astra` | `medium` |
| 機械轉換、資料抽取與結構化整理 | `gpt-6-luna` | `high`；簡單且可可靠驗證時 `medium` |

- main 預設 Astra Medium；orchestrate／task 預設 Sol 6.1 High。模型跟隨已確認角色與本表，不因等待、工具故障、缺資料或 task 數量升級，也不為混合配置增加常駐第四角色或自動委派。
- Sol 遇具體未解的根因／方法判斷瓶頸時，先列出問題、已有證據與嘗試、預期交付及停止條件，再依當次授權評估有界 xhigh 或 Astra 支援。沿用合適且已授權的執行者；需要加開時仍須建立任務授權，不重建整套分工或複製完整歷史。
- Astra main 以 Medium 為起點；重大研究／架構取捨或反覆漏掉關鍵需求時可評估 High，仍須具體理由與使用者明確授權。有界 Astra 支援也先用 Medium，只處理指定難題，結束後交回原執行者，不接手例行協調、等待或重做完整任務。
- 已授權新建 main 明確指定 `gpt-6-astra`／`medium`，orchestrate／task 預設指定 `gpt-6.1-sol`／`high`，其他模型依上表；不用舊 Sol ID 或漂移的 latest。既有對話、learn 與專利討論保留已確認設定；恢復前核對實際設定，差異僅說明，取得切換授權後才調整。不以工作訊息偷偷切換或喚醒暫停任務。
- 依不確定性、錯誤代價、可驗證性與總交付成本選擇。可用腳本／既有工具處理的機械步驟，不為模型分流增加新 task；不同模型的同名 effort 不代表能力或費用等價。

## 外部 task 的設定

- 外部 CLI task 的執行與驗收依 [外部執行指南](external-execution.md)。下列 Codex 的模型、effort 與速度預設不自動套用 agy 或其他工具；保留既有 Codex 任務配置，不因增加執行者切換模型。
- 使用該工具實際支援且已確認的模型／effort；任務或階段交接記錄工具版本、供應商、模型、effort 及其回傳核對結果。未指定時先提出合適配置並確認必要選型，不把工具預設或 latest 當成已確認值。
- 不因不同工具都稱 High 就視為能力或費用等價，也不照搬 Codex model ID。較深設定或更新模型不代表更有效率，不自動啟用額外付費、升級訂閱或全面提高深度。
- 規格清楚、容易驗證的簡單 task 可以外派；交接成本大於收益時沿用既有執行者。評估總用量、返工及完成時間，不以形式分工為由多開一層 Codex task。

## 深度、速度與升級

- Astra main Medium、Sol 6.1 orchestrate／task High 是起點；不全面提高 Sol 至 xhigh，其他模型依上表。「以後需要再修改」不代表自動升級授權，不因本政策修改全域模型 config。
- Extra High（`xhigh`）只有具體問題需要且當次授權允許才用；Max／Ultra 不作日常預設。不因額度剩餘自動提高，也不因單次消耗高就立即降低。
- 先核對需求、資料、工具、環境與相依，再處理反覆漏約束、根因判斷不足與無效修正。工具故障、批准阻礙、缺資料與純等待，不能靠升級模型解決。
- Effort 與速度分開。新任務工具可指定速度且無另行要求時使用 Standard；High 不代表 Fast。工具沒有速度欄位時不宣稱已設定或驗證 Standard。
- 更深推理不保證更快、更正確，仍須完成與風險相稱的驗證。追求總交付效率、減少返工與人工介入，不追求最低單次 token 或用完額度。

## 實際設定與權限

- 只有任務建立已獲授權才使用上述預設；本指南不授權新建任務、改設定檔或切換現有模型。延續既有 task 時保留既有設定，除非使用者另有授權。
- 工具支援時在參數明確傳入 model／effort，不只在 prompt 中描述。以工具回傳或可查詢設定核對；僅知道送出參數時應說「已請求」，不可說已驗證實際執行設定。
- 指定模型不可用時不擅自替代；說明工具限制與已知狀態，繼續不依賴該選型的工作。不為更換模型另開重複 task。
- Subagents 可按同一原則選型；若只能繼承則接受並如實說明，不假設使用較低成本模型。提供足夠背景與範圍，結果仍由 task 核對。

## 評估與版本

- 優先利用數個代表性完整任務的完成時間、人工介入、返工、驗收及用量判斷，不看單次回答長短。
- 不自行建立額外 benchmark、重跑完整工作或新增監控；額外實驗需先確認範圍。外部評測只提供起點，不能取代本專案證據。
- 模型更名、可用性或政策更新時，保留此版本的已確認 ID，經使用者決策後更新；不把查到的新模型自動替換進配置。

歷史決策（預設已由 2026-10-12 政策取代）：2026-09-30 使用者確認新增兩項彈性中的模型部分：新建例行調度或機械處理可依難度用 Medium，其餘主要工作維持 High。所有既有任務設定與授權邊界保留。


## 2026-10-02 模型更新

使用者要求因應 Codex 新模型更新配置並合併、推送。原本使用 `gpt-6-sol` 的新建任務改為 `gpt-6.1-sol`；當時 Astra／Luna 的角色及 High／Medium 原則保留；現行設定以上方 2026-10-13 政策為準。本文的 Sol 簡稱皆指表中 GPT-6.1 Sol，不使用會自行漂移的 latest 別名。

[官方模型頁](https://developers.openai.com/api/docs/models/gpt-6.1-sol)將 GPT-6.1 Sol 定位為兼顧複雜工作能力與成本的選擇，支援本政策使用的 Medium／High；[模型家族指南](https://developers.openai.com/api/docs/guides/latest-model)仍區分 Astra、Sol、Luna。這支持延續原分工，但不是此配置已在使用者專案勝過其他配置的實驗證據。

本次也核對了 Codex 派工工具列出的 `gpt-6.1-sol` 和 `medium`／`high` 可選值；模型實際可用性仍需逐次依執行端工具核對。API 文件與 Codex UI／派工工具的 effort／速度選項不保證完全相同，不互相推定。更新指示不會變更現有對話、全域預設模型或訂閱權限。
