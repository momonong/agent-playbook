# 模型與推理深度

這是使用者對**已授權新任務與 subagents**的配置政策，不是模型能力保證、官方最佳設定或切換既有對話的授權。主對話模型與 effort 由使用者決定。

## 預設配置

| 工作 | 模型 ID | Effort |
|---|---|---|
| 新 main：需求、研究假設與重要取捨 | `gpt-6-astra` | `high` |
| 新 orchestrate：相依、整合及階段判斷 | `gpt-6.1-sol` | `high` |
| 新 orchestrate：規格已定、例行調度，容易核對 | `gpt-6.1-sol` | `medium` 可選，仍需判斷時用 `high` |
| 一般與複雜開發 task | `gpt-6.1-sol` | `high` |
| 高不確定性、困難根因、重大架構取捨、持續深度判斷的研究實作 task | `gpt-6-astra` | `high` |
| 明確、小範圍、容易驗證的局部修改 | `gpt-6.1-sol` | `medium` |
| 機械轉換、資料抽取與結構化整理 | `gpt-6-luna` | `high` 預設；簡單且可可靠驗證時可用 `medium` |

- 新 orchestrate 若確需高度不確定的跨系統規劃，可選 Astra High；不因 task 多、等待久或單純轉傳就升級。
- Sol 可以負責完整的複雜工程工作，不限於 Astra 規劃後的微型實作。明顯需要 Astra 的工作可直接選，不要求先讓小模型失敗。
- 依模糊程度、相依、錯誤代價、可驗證性與完整交付成本選擇，不按角色名稱或「架構／除錯／重構」關鍵字機械分類。
- Luna High 不等於 Sol High 或 Astra High；模型能力與 effort 分別判斷。可可靠使用腳本、schema 或既有工具處理的機械步驟，不為模型分流增加新任務。

## 深度、速度與升級

- High 是需要持續分析與工程判斷工作的預設；小型明確工作、例行調度及可可靠驗證的機械處理可用 Medium。這是新建時的選型，並不授權切換既有設定。
- Extra High（`xhigh`）只有具體問題需要且當次授權允許才用；Max／Ultra 不作日常預設。不因額度剩餘自動提高，也不因單次消耗高就立即降低。
- 先核對需求、資料、工具、環境與相依，再處理反覆漏約束、根因判斷不足與無效修正。工具故障、批准阻礙、缺資料與純等待，不能靠升級模型解決。
- Effort 與速度分開。新任務工具可指定速度且無另行要求時使用 Standard；High 不代表 Fast。工具沒有速度欄位時不宣稱已設定或驗證 Standard。
- 更深推理不保證更快、更正確，仍須完成與風險相稱的驗證。追求總交付效率、減少返工與人工介入，不追求最低單次 token 或用完額度。

## 實際設定與權限

- 只有任務建立已獲授權才使用上述預設；本指南不授權新建任務、改設定檔或切換現有模型。延續既有 task 時保留既有設定，除非使用者另有授權。
- 工具支援時在參數明確傳入 model／effort，不只在 prompt 中描述。以工具回傳或可查詢設定核對；僅知道送出參數時應說「已請求」，不可說已驗證實際執行設定。
- 指定模型不可用時不擅自替代；說明工具限制與已知狀態，繼續不依賴該選型的工作。不為更換模型另開重複 task。
- Subagents 可按同一原則選型；若只能繼承則接受並如實說明，不假設使用較低成本模型。提供足夠背景與範圍，結果仍由 task 核對。

## 評估與版本

- 優先利用數個代表性完整任務的完成時間、人工介入、返工、驗收及用量判斷，不看單次回答長短。
- 不自行建立額外 benchmark、重跑完整工作或新增監控；額外實驗需先確認範圍。外部評測只提供起點，不能取代本專案證據。
- 模型更名、可用性或政策更新時，保留此版本的已確認 ID，經使用者決策後更新；不把查到的新模型自動替換進配置。

2026-09-30 使用者確認新增兩項彈性中的模型部分：新建例行調度或機械處理可依難度用 Medium，其餘主要工作維持 High。所有既有任務設定與授權邊界保留。


## 2026-10-02 模型更新

使用者要求因應 Codex 新模型更新配置並合併、推送。原本使用 `gpt-6-sol` 的新建任務改為 `gpt-6.1-sol`；Astra／Luna 的角色及 High／Medium 原則保留。本文的 Sol 簡稱皆指表中 GPT-6.1 Sol，不使用會自行漂移的 latest 別名。

[官方模型頁](https://developers.openai.com/api/docs/models/gpt-6.1-sol)將 GPT-6.1 Sol 定位為兼顧複雜工作能力與成本的選擇，支援本政策使用的 Medium／High；[模型家族指南](https://developers.openai.com/api/docs/guides/latest-model)仍區分 Astra、Sol、Luna。這支持延續原分工，但不是此配置已在使用者專案勝過其他配置的實驗證據。

本次也核對了 Codex 派工工具列出的 `gpt-6.1-sol` 和 `medium`／`high` 可選值；模型實際可用性仍需逐次依執行端工具核對。API 文件與 Codex UI／派工工具的 effort／速度選項不保證完全相同，不互相推定。更新指示不會變更現有對話、全域預設模型或訂閱權限。
